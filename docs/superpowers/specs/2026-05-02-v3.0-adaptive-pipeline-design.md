# v3.0 Design: The Adaptive Pipeline

**Status:** Draft Spec  
**Date:** 2026-05-02  
**Topic:** v3.0 Adaptive Pipeline for Sports Card Extraction

## 1. Problem Statement
The v2.x series relied on fixed thresholds (confidence, blur, temporal gaps) that caused missed detections during focus hunting or false-positive track splits during heavy glare. v3.0 moves to an "Adaptive Pipeline" that uses relative metrics and geometric awareness to harden the system.

## 2. Core Architecture: The Wide Funnel
We transition from a "Filter Early" to a "Filter Late" approach.
1. **Ingestor (Wide Funnel):** Captures more potential frames using relative quality metrics.
2. **Refinery (The Filter):** Uses spatial tracking, geometric flip detection, and visual deduplication to consolidate and validate the raw data.

---

## 3. Pipeline Stages

### Stage 1: Adaptive Quality Triage (Ingestion)
- **Mechanism:** Rolling-window percentile filter.
- **Logic:** Calculate sharpness in 30-frame chunks. Pass the top 50% sharpest frames from each chunk to the detector.
- **Benefit:** Ensures we never miss a card during "soft" focus segments of a video.

### Stage 2: Hysteresis-Based Tracking
- **Initialization Threshold ($T_{high}$):** $0.55$.
- **Maintenance Threshold ($T_{low}$):** $0.20$.
- **Logic:** Once a high-confidence detection starts a track, it remains active even if confidence drops (due to glare), as long as the centroid stays within 75px of the previous position.
- **Verification:** Discard any track shorter than 3 frames.

### Stage 3: Geometric Flip Detection
- **Mechanism:** Polygon Area Monitoring.
- **Logic:** Monitor the area of the 4 detected corners.
- **Split Condition:** A "collapse" in area (to $<40\%$ of median) followed by an "expansion" (to $>80\%$) within 10 frames triggers a track split.
- **Tags:** Pre-split = `Angle: Front`, Post-split = `Angle: Back`.

### Stage 4: Precision Normalization
- **Dimensions:** $750 \times 1050$ pixels.
- **Inner Crop:** $1.5\%$ safety margin applied post-homography to remove background bleed.
- **Interpolation:** `cv2.INTER_LANCZOS4`.

### Stage 5: Visual Deduplication
- **Mechanism:** pHash (Perceptual Hashing) of the **inner 60%** of the card.
- **Threshold:** Hamming distance $< 4$ ($\sim95\%$ match).
- **Policy:** Flag matches in the database but do not auto-merge by default (quantity handled out-of-band).

### Stage 6: Lighting-Diverse Selection & Fusion
- **Selection:** Partition the card into 4 quadrants. Select the sharpest frame from each quadrant where a glare center is detected.
- **Fusion:** Apply a **Median Pixel Blend** across the 3-4 selected frames to mathematically erase glare.
- **Artifact:** `fused_canonical.jpg`.

### Stage 7: Metadata & UI Refactor
- **Metadata:** Store Glare Center coordinates, sharpness heatmaps, and detection confidence as compressed arrays/JSON.
- **UI:** 
  - Display `fused_canonical.jpg` as the primary image.
  - Add "Source Frames" carousel for the raw lighting-diverse views.
  - Show "Angle" tags (Front/Back).

---

## 4. Implementation Phases

- **Phase A (Tracking):** Stages 1, 2, 3. Focus on `selector.py` and `pipeline.py`.
- **Phase B (Refinement):** Stages 4, 5. Focus on `cropper.py` and new `deduplicator.py`.
- **Phase C (Fusion & UI):** Stages 6, 7. Focus on `fuser.py` and `review.py`.

## 5. Constraints
- **Non-Destructive:** Fused images must be saved as new artifacts; raw evidence frames are preserved.
- **Performance:** Use `numpy` vectorization for all pixel-wise operations.
- **No Grading:** Strictly no condition or market value logic.
