# 4.1 Pipeline Debugging Summary

Date: 2026-05-12

This note records the evidence used to diagnose the 4.1 pipeline regression where a harness run saved only two blurry cards despite hundreds of detections.

## Starting Symptom

The pasted failing run showed:

- `334` ML detections.
- Novelty gate dropped `167 / 334` candidates before tracking.
- Tracking repeatedly reset across `29` sessions, mostly `valley_split` with small gaps such as `4f`.
- Only `5` tracks finalized.
- Only `2` cards saved.
- Telemetry: `windows=14`, `selected_frames=301`, `tracks=5`, `duplicates=3`, `t_high=0.728`.

The expected baseline has six unique cards in `IMG_5872.MOV`.

### Sampler Diagnostics

After tracing the sampler and regional split code, `card-capture sampler sessions /Users/josh/IMG_5872.MOV --expected 6` reported:

- `fast_scan_frames=555`
- `presence_windows=6`
- valley splits: `[176, 224, 612, 888, 1028, 1372, 1732, 2192]`
- predicted sessions: `6`

The same command previously had been misleading because the CLI was recomputing only the global split path instead of using the pipeline's combined global/regional split method.

### Regional Split Vote Analysis

Regional tile analysis on `IMG_5872.MOV` produced many one-off regional splits:

- `58` unique regional split frames before vote filtering.
- `41` of those had only one tile vote.
- Requiring at least `5` region votes reduced the regional output to the same practical split set as the global detector.

That supported adding a region-vote threshold plus coalescing near-adjacent split frames.

### Detector Confidence Checks

Targeted frame checks showed that missing truth windows did have usable detections, but several were below the previous adaptive tracker high threshold:

- Around card 4: frame `1228` confidence `0.732`, frame `1232` confidence `0.707/0.574`, frame `1240` confidence `0.762`.
- Around card 5: frame `1408` confidence `0.705`, frame `1500` confidence `0.675`, frame `1560` confidence `0.632`, frame `1620` confidence `0.596`.

The failing run's `t_high=0.728` was high enough to suppress real card sessions. Capping tracker high threshold at `0.60` kept these tracks reachable.

### Novelty Score Checks

Candidate and persisted track novelty scores showed that hard novelty pruning was unsafe:

- Most true cards had track novelty medians around `0.14-0.16`.
- One real early card had median novelty around `0.021`, overlapping low-novelty false tracks.

Any hard novelty threshold high enough to remove those false tracks would also remove that true card. The fix keeps novelty scores for telemetry/adaptive scoring, but disables hard novelty pruning.

### Saved Crop Quality

The latest full harness persisted `8` saved crops for video id `10`, all rectified to `1050x750`.

Per-instance sharpness in SQLite showed a mix:

- Some canonical sharpness values were still low, such as `0.07-0.09`.
- Others improved, such as `0.28-0.47`.

This means the original "only two blurry cards" failure was fixed by restoring recall and track coverage, but crop selection/sharpness remains a separate follow-up improvement area.

## Root Causes

1. Regional valley split indices were in the wrong coordinate system.

   `find_valley_splits_per_region()` returned scan-array indices, but the tracker reset path expected source frame indices. This produced many false split boundaries and fragmented tracking into many short sessions.

2. Regional valley splits needed consensus filtering.

   Per-tile glare/background changes produced many single-region split votes. Without a minimum vote count and coalescing, the combined split set was too noisy.

3. The sampler diagnostic command did not match pipeline behavior.

   It bypassed the pipeline's combined global/regional `_compute_valley_splits()` path, hiding the actual reset behavior during debugging.

4. Novelty pruning was a false-negative source.

   Background novelty is useful as a signal, but not as a hard gate for this video because at least one true card has low novelty against the workspace background.

5. The adaptive tracker high threshold was too aggressive.

   The detector produced real card confidences in the `0.59-0.72` range. Allowing `t_high` to rise to about `0.728` blocked real tracks.

6. Track accumulation across resets was duplicating finalized tracks.

   The adapter already keeps finalized tracks internally. Accumulating reset returns again at the pipeline layer inflated duplicate storage.

## Code Changes

- `src/card_capture/sampler/valley_detection_per_region.py`
  - Added `frame_indices` mapping so regional split outputs are source frame indices.
  - Added `min_region_votes`.

- `src/card_capture/sampler/__init__.py`
  - Added coalescing helpers for nearby split frames.
  - Passed `frame_indices` and `min_region_votes=5` into per-region detection.

- `src/card_capture/cli.py`
  - Updated `sampler sessions` to call `sampler._compute_valley_splits(scan_frames)`.

- `src/card_capture/pipeline.py`
  - Changed novelty to score-only collection.
  - Disabled hard track-level novelty pruning with threshold `0.0`.
  - Capped tracker high threshold at `0.60`.
  - Removed duplicate pipeline-level accumulation of tracks finalized during resets.
  - Made canonical entry quality selection tolerate older entry shapes.

- `src/card_capture/tracking/botsort_adapter.py`
  - Set internal BoT-SORT `min_hits=1`; pipeline-level `min_track_length` remains the confirmation gate.
  - Tied `new_track_thresh` to the adapter activation threshold.
  - Set `track_low_thresh` to `max(0.1, activation - 0.20)`.

- Tests updated:
  - `tests/test_sampler_fast_scan.py`
  - `tests/test_botsort_adapter.py`
  - `tests/test_pipeline.py`
