# Card Capture v2.3 Architecture Specification: Spatial Tracking & Instance Separation

**Project:** Sports Trading Card Image Extraction from Video  
**Target Audience:** Implementation LLM / Coding Agent  
**Status:** Approved Architecture Specification (Extension of v2.2)
**Objective:** Resolve the temporal grouping bottleneck in `selector.py` that causes aggressive false-positive deduplication of rapidly presented cards.

## 1. Architectural Mandate

The legacy `CandidateSelector.select()` logic relies on a fixed `group_gap_ms` (1000ms) to separate card instances. This algorithm has been deprecated because it fails when multiple unique cards are presented sequentially within a single continuous time window.

You are instructed to rewrite the grouping and selection logic in `selector.py` to use **Spatial Clustering** (corner coordinate tracking) as the primary method for instance separation, falling back to temporal gaps only when spatial tracking breaks.

---

## 2. Pipeline Modifications: Redesigning `selector.py`

### Step 1: Implement Spatial Centroid Tracking
* **Action:** Before grouping detections, calculate a "Centroid" (the average X and Y coordinate) for the 4 detected corners of every frame.
* **Logic:** 1. Sort all detections chronologically.
  2. Start a `Cluster` with the first detection.
  3. Look at the next chronological detection. Compare its Centroid to the previous frame's Centroid.
  4. **The Split Condition:** If the Euclidean distance between the centroids is *less than* a defined threshold (e.g., `spatial_variance_threshold = 75` pixels), append it to the current `Cluster`. If the distance is *greater than* the threshold, close the current `Cluster` and start a new one.

### Step 2: Hybrid Grouping (Spatial + Temporal)
* **Action:** Combine the new spatial threshold with a reduced temporal threshold.
* **Logic:** A new `Cluster` (representing a unique card instance or a new front/back view) should be spawned if **EITHER** of the following is true:
  * The spatial distance between consecutive frames exceeds the `spatial_variance_threshold` (the card was flipped or moved significantly).
  * The time gap between consecutive frames exceeds a shortened `group_gap_ms` (e.g., `300ms`).

### Step 3: Multi-Instance Selection Strategy
* **Action:** Modify the yield/return logic of `CandidateSelector.select()`.
* **Legacy Logic (Remove):** Selecting 1 best frame per temporal group, capped by a global `max_candidates`.
* **New Logic (Implement):** 1. Treat every completed `Cluster` from Step 2 as a unique `CardInstance`.
  2. For *each* `Cluster`, sort the internal frames by confidence/quality score.
  3. Select the top `N` frames per cluster (e.g., `frames_per_instance = 1` or `2` for lighting diversity, connecting to the v2.2 fusion pipeline).
  4. Return the aggregated selections across all clusters. (Do not arbitrarily cap the global selections to 10 if there are more than 10 valid clusters).

---

## 3. Front/Back Angle Differentiation (Heuristic)

Until a dedicated classification model is trained, the Spatial Clustering acts as a natural Front/Back separator.

* **Mechanism:** When a user physically flips a card from front to back, the corners will move significantly, or their hands will temporarily obscure the card, causing a brief drop in detection. 
* **Outcome:** The spatial distance threshold (Step 1) or the shortened temporal gap (Step 2) will naturally trigger a split. The front of the card will become `Cluster A`, and the back of the card will become `Cluster B`. The system will then automatically pick the highest quality frame for both angles independently.

---

## 4. Implementation Directives for LLM Agent

1. **Target File:** Focus your refactoring exclusively on `src/card_capture/selector.py` (and relevant config/models).
2. **Data Structure:** Utilize the existing 8-float corner coordinates `[x1, y1, x2, y2, x3, y3, x4, y4]` provided by the detection payload to compute the centroids.
3. **Threshold Configuration:** Expose `spatial_variance_threshold` as a configurable parameter (default to `75.0` pixels) alongside the existing `group_gap_ms`.
4. **Testing:** Write unit tests that mock a continuous 500ms time window where the corner coordinates suddenly jump by 200 pixels halfway through. Assert that the `CandidateSelector` yields *two* selections (one from each spatial position) rather than just the single highest-confidence frame overall.
