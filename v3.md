# Card Capture v3 Architecture Specification: The Adaptive Pipeline

**Project:** Sports Trading Card Image Extraction from Video  
**Target Audience:** Implementation LLM / Coding Agent  
**Status:** Approved Architecture Specification (Replaces v2.2 and v2.5 proposals)
**Objective:** Implement a fully adaptive, multi-view extraction pipeline featuring hysteresis tracking, precision normalization, multi-frame fusion, and global deduplication.

## 1. Architectural Mandate

This version deprecates the use of brittle, hard-coded thresholds (e.g., fixed confidence limits, rigid temporal gaps) in favor of adaptive, relative, and geometrically verified tracking. 

The pipeline transitions to a "Wide Funnel" approach: ingest low-confidence data early to ensure zero missed cards, then use spatial tracking, geometric flip detection, and visual deduplication to rigorously filter out noise at the end.

---

## 2. The v3 Pipeline Stages

### Stage 1: Adaptive Quality Triage (Ingestion)
* **Goal:** Never miss a card during early-video focus hunting.
* **Action:** Deprecate hard Laplacian variance thresholds. Implement a rolling window or relative percentile filter. 
* **Logic:** Calculate the sharpness of frames in sequential chunks (e.g., 30 frames). Pass the top 50% sharpest frames from *each chunk* to the detector. This guarantees the detector sees the best available frames, even if the entire video is slightly soft.

### Stage 2: Hysteresis-Based Detection & Tracking
* **Goal:** Track cards through extreme glare without spawning false positives.
* **Action:** Implement two-tier confidence tracking combined with Spatial Centroid clustering.
* **Logic:** 1. **Initialization:** A new `CardInstance` (Cluster) can only be spawned if a detection exceeds a high confidence threshold (e.g., `0.55`).
    2. **Maintenance:** Once a `CardInstance` is active, append consecutive frames to it as long as they fall within the spatial boundary (e.g., `< 75px` centroid shift), even if their detection confidence drops as low as `0.20`.
    3. **Verification:** Discard any `CardInstance` that only exists for 1 or 2 frames (noise).

### Stage 3: Geometric Flip Detection (Front/Back Separation)
* **Goal:** Ensure card fronts and backs are grouped into separate clusters, preventing the detector's bias toward card backs from overwriting valid front views.
* **Action:** Monitor the polygon area and bounding box aspect ratio of the 4 detected corners.
* **Logic:** If a tracked `CardInstance` undergoes a rapid collapse in polygon area (>50% drop) followed by an expansion, split the track. Tag the pre-split cluster as `Angle: Front` and the post-split cluster as `Angle: Back`.

### Stage 4: Precision Normalization & Cropping
* **Goal:** Ensure absolute pixel-grid consistency across all extracted images.
* **Action:** Apply strict mathematical cropping to the homography-warped images.
* **Logic:** 1. Define a global target resolution (e.g., `750x1050` pixels).
    2. Apply a 1-2% "inner crop" (safety margin) to remove residual background bleed.
    3. Resample the crop to the exact global target resolution using `cv2.INTER_LANCZOS4`.

### Stage 5: Global Visual Deduplication
* **Goal:** Prevent identical cards shown at different times from creating duplicate database entries.
* **Action:** Visually hash the inner artwork of normalized views.
* **Logic:** 1. Extract the center 60% of the normalized `CardView` (ignoring highly variable border glare).
    2. Compute a perceptual hash (pHash) or ORB descriptors.
    3. Compare against all previously validated `CardInstances`. If a >95% match occurs, merge the temporal instances.

### Stage 6: Lighting-Diverse Selection & Multi-Frame Fusion
* **Goal:** Generate a single, glare-free "Display Image" while preserving lighting variants for future refractor/foil analysis.
* **Action:** 1. **Selection:** For each validated, deduplicated `CardInstance`, select 3 to 4 normalized views where the spatial center of the glare (brightest pixels) is located in different physical regions of the card.
    2. **Fusion:** Because the selected views share an identical `750x1050` pixel grid, apply a Minimum or Median pixel-blend across the image stack. This mathematically erases moving glare spots, creating a clean composite (`Fused_Canonical_View`).

### Stage 7: Metadata Telemetry & UI Refactor
* **Goal:** Store the exact mathematical journey of the extraction for future ML grading pipelines and update the user interface.
* **Action:** 1. **Storage:** Save the binary Glare Masks, Laplacian heatmaps, and initial confidence scores as compressed arrays alongside the SQLite DB entry.
    2. **UI:** Update the Flask/FastAPI review UI to display the `Fused_Canonical_View` as the main image, with a carousel/filmstrip below it containing the raw, Lighting-Diverse `CardViews` used to create the composite.

## 3. Implementation Directives for LLM Agent

1. **Incremental Execution:** This is a massive architectural upgrade. Do not attempt a single-pass implementation. Build and test sequentially:
    * *Phase A:* Stages 1, 2, and 3 (Adaptive ingestion and tracking logic).
    * *Phase B:* Stages 4 and 5 (Normalization and Deduplication).
    * *Phase C:* Stages 6 and 7 (Fusion, Metadata, and UI).
2. **Non-Destructive Fusion:** The Multi-Frame Fusion (Stage 6) must never overwrite raw evidence frames. It generates a new, derived artifact.
3. **No Grading Features:** Strictly avoid implementing any logic that attempts to score the physical condition, centering, or market value of the card.
